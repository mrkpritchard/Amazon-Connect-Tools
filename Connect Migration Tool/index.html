Cross-Account Role Setup Guide

▼ Expand

If the source or target Connect instance is in a different AWS account, you must create an IAM role in that account and paste its ARN into the Cross-Account Role ARN field above. Same-account migrations do not require this step.

Step 1 — Find the Lambda Execution Role ARN

You need the ARN of this tool's Lambda execution role to place in the trust policy.

  1. Open AWS CloudFormation in account YOUR_AWS_ACCOUNT_ID (us-east-1)
  2. Find stack ConnectMigration-API → Resources tab
  3. Copy the Physical ID (ARN) of MigrationFunctionRole

Step 2 — Create IAM Role in the Cross-Account

In the other AWS account, go to IAM → Roles → Create Role, select Another AWS account, and enter account ID YOUR_AWS_ACCOUNT_ID. Then switch to Custom trust policy and paste:

Trust Policy

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "AWS": "<MigrationFunctionRole ARN from Step 1>"
      },
      "Action": "sts:AssumeRole"
    }
  ]
}

Permissions Policy (attach as inline policy)

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "connect:ListInstances",
        "connect:DescribeInstance",
        "connect:ListQueues",
        "connect:CreateQueue",
        "connect:ListContactFlows",
        "connect:DescribeContactFlow",
        "connect:CreateContactFlow",
        "connect:ListRoutingProfiles",
        "connect:DescribeRoutingProfile",
        "connect:CreateRoutingProfile",
        "connect:ListSecurityProfiles",
        "connect:CreateSecurityProfile",
        "connect:ListHoursOfOperations",
        "connect:CreateHoursOfOperation",
        "connect:ListUsers",
        "connect:CreateUser",
        "connect:ListQuickConnects",
        "connect:CreateQuickConnect",
        "connect:ListPredefinedAttributes",
        "connect:DescribePredefinedAttribute",
        "connect:CreatePredefinedAttribute",
        "connect:ListUserProficiencies",
        "connect:AssociateUserProficiencies"
      ],
      "Resource": "*"
    }
  ]
}

Step 3 — Copy the Role ARN and Paste Above

  1. Name the role e.g. ConnectMigrationCrossAccountRole
  2. Click Create role
  3. Open the newly created role and copy its ARN (format: arn:aws:iam::<account-id>:role/ConnectMigrationCrossAccountRole)
  4. Paste the ARN into the Cross-Account Role ARN field for the appropriate instance above
  5. Click Test Connection to verify
⚠️ Note: If both source and target are in different accounts, create a role in each account and enter both ARNs. If only one is cross-account, only that one needs a role. Roles are not needed for same-account migrations.
